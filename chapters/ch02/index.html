2.1 · FOR

for 循环：固定次数重复

「让某段代码执行 n 次」是循环最常用的场景，for 循环就是为它设计的。

1. for 的三要素

for 循环的结构是 for(初始化; 条件; 更新)，执行顺序是：初始化 → 判断条件 →（成立则执行循环体）→ 更新 → 再判断…

程序 2-2 · 输出 1 到 nC
int n, i;
scanf("%d", &n);
for (i = 1; i <= n; i++)
  printf("%d\n", i);

i 从 1 数到 n，每数一个数就输出一次，一共输出 n 个数。最容易错的是边界：i <= n 会执行 n 次，写成 i < n 就只有 n-1 次。

2. 累加：s += i

程序 2-3 · 计算 1+2+…+nC
int n, i, s = 0;       /* 累加器要先清零 */
scanf("%d", &n);
for (i = 1; i <= n; i++)
  s += i;              /* s = s + i */
printf("%d\n", s);

累加器 s 的初值必须是 0。这个「先清零、再累加」的模式后面会反复出现（求和、计数、找最值……）。

2.2 · WHILE

while 与 do-while：条件说了算

不知道循环多少次，但知道「什么时候停」——这种情况交给 while。

1. while：先判断，再执行

while 每次执行前都检查条件，条件为真才执行循环体。如果一开始条件就不成立，循环体一次都不执行。

程序 2-4 · 读入数字直到遇到 0C
int x;
scanf("%d", &x);
while (x != 0) {      /* 0 是结束标记 */
  printf("处理：%d\n", x);
  scanf("%d", &x);   /* 再读下一个 */
}

这里「以 0 结尾」是数据约定。while 的常见配套习惯：在循环体末尾更新条件变量，否则会死循环。

2. do-while：先执行一次再说

do-while 先执行循环体，再判断条件，因此至少执行一次。适合「必须先做一次，再看要不要继续」的场景。

程序 2-5 · 至少输出一次C
int x;
do {
  printf("你输入的是 %d\n", x);
  scanf("%d", &x);
} while (x != 0);

⚠死循环排查

程序卡住不动、一直刷屏，多半是死循环。先在循环体里加一句 printf("i=%d\n", i); 看变量是怎么变的，通常一眼就能看出「条件永远为真」的原因。

2.3 · COST

循环的代价：你的程序要跑多久

循环越深、越慢。学会估算循环次数，是后面学习「高效算法」的起点。

1. 数循环次数

一层循环跑 $n$ 次，工作量记为 $O(n)$；两层嵌套循环，外层 $n$ 次、内层 $n$ 次，总共约 $n \times n = n^2$ 次，记为 $O(n^2)$。现代评测机一秒大约能跑 $10^8$ 次简单操作，超过这个量级就会超时。

程序 2-6 · 嵌套循环：输出乘法表的一部分C
int i, j;
for (i = 1; i <= 3; i++)      /* 外层 3 次 */
  for (j = 1; j <= 3; j++)    /* 内层 3 次 */
    printf("%d*%d=%d\n", i, j, i * j);  /* 共 3×3=9 行 */

2. 一张表记住量级

O$O(n)$：线性

n=10⁶ 的简单循环没问题，约 1 秒。

O$O(n^2)$：平方

n=10⁴ 就到 10⁸ 了，再大就要超时。

O$O(n \log n)$

排序等常用算法的量级，n=10⁶ 也很快。

O避免无用重复

能在循环外算的，别放循环里算。

小测｜嵌套循环次数O(n²)

2.4 · I/O

输入输出框架：多组数据怎么办

OJ 题目经常不告诉你「有几组数据」，而是让你读到文件尾（EOF）。这一节给出标准写法。

1. scanf 的返回值

scanf 的返回值是成功读入的变量个数。如果输入流已经到末尾、什么都读不到，它返回 EOF（一个负数）。利用这一点，可以写出「一直读到文件尾」的循环：

程序 2-7 · 多组数据：两个数求和，读到文件尾C
#include <stdio.h>

int main() {
  int a, b;
  while (scanf("%d%d", &a, &b) == 2) {
    printf("%d\n", a + b);
  }
  return 0;
}

读入 2 个变量成功就进入循环；一旦读不到（EOF），scanf 返回不是 2，循环自然结束。这是竞赛里最常用的输入框架之一。

因为数据的组数我们不知道：可能是 1 组，也可能是 10 万组。for 需要「提前知道次数」，而 while 只看条件——「还能读到吗？能就读」，天然适合处理数量未知的输入。
