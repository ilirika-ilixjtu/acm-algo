4.1 · FUNCTION

自定义函数：把功能打包

函数让你「写一次，用很多次」，还能让主程序像读故事一样清楚。

1. 函数的样子

一个函数由三部分组成：返回类型、函数名、参数列表。函数体里的 return 值; 把结果交回给调用者。

程序 4-2 · 判断素数C
#include <stdio.h>

int is_prime(int x) {         /* 返回 1 表示是素数，0 表示不是 */
  int i;
  if (x < 2) return 0;
  for (i = 2; i * i <= x; i++)
    if (x % i == 0) return 0;  /* 找到因子，直接返回 */
  return 1;
}

int main() {
  int n;
  scanf("%d", &n);
  if (is_prime(n)) printf("YES\n");
  else printf("NO\n");
  return 0;
}

注意 i * i <= x：检查到 $\sqrt{x}$ 就够了，这是判断素数的标准优化。函数一旦 return 就立刻结束，后面的代码不再执行。

2. 函数的好处

✓复用

同一个功能（判断素数、求阶乘）写一次，到处调用。

✓清晰

main 函数只描述「做什么」，细节藏进函数里。

✓好测

单独测一个函数比测整个程序容易得多。

✓递归基础

函数能调用自己，这是下一节递归的前提。

4.2 · PARAM

函数调用与参数传递

C 默认按值传参；想改外面的变量，就得传指针。这是新手最容易绕晕的一关。

1. 值传递：传的是副本

f(a) 调用时，系统把 a 的值复制一份给形参。函数里改形参，改的是副本，外面的 a 毫发无损。

程序 4-3 · 想交换 a、b？按值传不行C
void swap_bad(int x, int y) {   /* x、y 是副本 */
  int t = x; x = y; y = t;      /* 只换了副本 */
}

void swap(int *pa, int *pb) {   /* 传地址 */
  int t = *pa; *pa = *pb; *pb = t;  /* 改真正的值 */
}

int main() {
  int a = 3, b = 5;
  swap_bad(a, b);   printf("%d %d\n", a, b);  /* 3 5，没换 */
  swap(&a, &b);    printf("%d %d\n", a, b);  /* 5 3，换了 */
  return 0;
}

*pa 表示「pa 指向的那个变量」。传 &a 就是告诉函数 a 住在哪里，函数就能直接改它。

4.3 · RECURSION

递归：函数调用自己

递归不是「循环的替代品」，而是一种全新的思维方式：把大问题拆成更小的同类问题。

1. 递归的两块拼图

①递归出口（基线条件）

最简单的情况直接给答案，不再调用自己。没有出口 = 无限递归 = 栈溢出。

②递归步骤

把问题缩小，用「更小的自己」算出结果，再组合成大问题的答案。

程序 4-4 · 递归求阶乘C
int fac(int n) {
  if (n == 0) return 1;        /* 出口：0! = 1 */
  return n * fac(n - 1);       /* 步骤：n! = n × (n-1)! */
}

2. 可视化：fac(4) 的调用栈

每调用一次函数，系统就往栈上「压入」一个帧，记录局部变量和返回地址；函数返回时「弹出」。下面一步步看：

3. 追踪递归的三个技巧

① 先找出口：n=0 返回 1，这是递归的「地基」。
② 相信子问题：别一层层展开，假设 fac(n-1) 已经算对了。
③ 注意深度：递归太深（如 10 万层）会栈溢出，后面学「递推」来避免。

4.4 · DEBUG

段错误、栈溢出与调试

RE（运行时错误）大多是段错误；学会定位，比赛里能省下大量时间。

1. 两种常见崩溃

!段错误（Segmentation Fault）

访问了不该访问的内存：数组越界、空指针、scanf 忘写 &。通常一行定位：看 RE 前最后一次输出在哪个 printf 附近。

!栈溢出（Stack Overflow）

递归太深或局部数组太大，把栈内存用光。对策：改递推、减小局部数组、加大数组到全局。

2. 调试三板斧

① printf 大法：在关键位置打印变量，看程序走到哪、值是什么。
② 小数据手算：拿一个 3、4 这样的小样例，把每一步在纸上走一遍。
③ 对拍：写一个暴力「笨办法」，和你的算法在小数据上比结果。
